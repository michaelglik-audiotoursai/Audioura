## Why `tour_content` is NULL and when it won't be

Tour 355 was generated by the **thread-mode orchestrator** which stores tour content in the in-memory `ACTIVE_JOBS` dict but doesn't reliably persist `tour_content` to the `audio_tours` table (the store_audio_tour path may not pass it). After the **Cloud Tasks deploy**, the worker calls `store_audio_tour` with `tour_content` populated → new tours will use the primary path (`translate_tour_with_audio` with `tour_content`), which already handles per-stop translation correctly.

The fallback path (now fixed) handles all legacy tours.

## What was built (`audio_tour_app/`)

| `services/on_the_way_controller.dart` | State machine stop / countdown / topic / quiet; 5 s countdown; skip; menu choose; Quiet; "Play a topic"; arrival (sentence-end fade, resume offer); `mapMediaNext`. |

| `services/on_the_way_notification.dart` + `notification_service.dart` + `main_screen.dart` | Ongoing notification with a "Topics" action (Android action / iOS category) → opens the same sheet. MainScreen no longer resets the Listen tab for this notification. |

## Behaviour by spec item
1. **State always visible**: "Stop 3 of 8 · title"; "On the way to Stop 4 · ~25 min" + "Now: title · 12 min · Theme" in an amber card with an "Optional" badge on a green (not slate) bar; "… · quiet" + big "Play a topic". Leg minutes are shown to the nearest 5 (≥10 min).
2. **Auto-play**: first item after a 5 s countdown ("Next: title — Skip"); next items follow the same way; settings for auto-play and "always quiet" (= feature fully off, player unchanged).
3. **Hands-free skip**: `mapMediaNext`: stop → today's `next()`; countdown/topic → skip topic (next menu item, after last item silence); in silence a *hardware* "next" is **ignored** (my decision, so an extra press does not jump into the next stop early; the on-screen bar button still goes to the next stop).
4. **Menu**: rows with title, minutes, theme, ▶; "Quiet"; reachable from the panel and from the notification action.
5. **Arrival**: GPS reaches a stop during a topic → fade at the end of the current sentence (`sentence_ends`, ≤20 s wait) else at once, then the stop plays; "Resume <topic> later" is shown on the next leg and continues from the saved position. An interrupted topic sends no `skip` (not penalised).
6. **Credits**: the credit line is shown under the title; "Sources" link when a URL exists (see gaps).
7. **Events**: `start`, `skip`(+`at_sec`), `finish`, `choose` (menu ▶ sends `choose` then `start`); "Play a topic" sends `start`; Quiet sends nothing.
8. **Old payload**: no `fillings` → no controller, no panel, no JS, no hold, nothing changes (tested).
9. **Translations**: items whose `language` ≠ the tour language are hidden (default) or kept with "Topics available in English" (setting).

## NOT proven / gaps — for LEAD
- **Fillings do not reach the device yet.** The app reads `fillings.json` (or `tour.json`) inside the downloaded tour folder; 907 only puts `fillings` in the in-memory status response and the delivery ZIP does not carry it. Backend must write it into the ZIP.
- **No source URL**: 907's `credit_line` has no URL and no `sources`, so the "Sources" link cannot appear with the real payload (it works if `sources`/`source_url`/a URL in the line is added). Likewise 907 sends no `language` and no `sentence_ends`: translation rule and sentence-end fade are inert until it does (fade-at-once is the fallback).
- **audio_url** is relative (`/topic-audio/…`); I join it to the orchestrator base — an assumption; nothing serves it yet. Topic audio needs a connection (or a `file://` URL).
- Not run: Android emulator; real Bluetooth/CarPlay/Android Auto/wheel "next" (only the mapping and the JS registration are tested); lock-screen notification action (only the shared menu signal was exercised); iOS WebKit ignores `audio.volume`, so the fade there is a stop after the same time.
- The 907 endpoint does not dedupe, so a retry after a lost response can double-count one event.
- Settings are in the sheet only (no global settings screen exists). The persistent bar's title still shows the stop name during a topic.
- Test harness: speech-recognition permission was pre-granted in the simulator TCC db to hide the voice prompt.

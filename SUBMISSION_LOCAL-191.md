## Summary

Michael's hypothesis is **confirmed**. Stop 1 is systematically different from
stops 2..N because a tour-level prolog (80-190 words, generated by a separate
LLM call) is injected into Stop 1's body at assembly time. This prolog
describes the *tour* — not the POI — making Stop 1 structurally a tour
description wearing a stop's clothes.

## 2. The mechanism (with line references)

**File:** `generate_tour_text.py`

### Prolog generation (lines 6316-6345)

```python
_prolog_prompt = f"""Write a compelling 80-190 word tour introduction that
frames this experience as a journey — a book of connected chapters.

Theme/connecting thread: {_connecting_thread}
Tour hook: {_tour_hook}
Chapter previews: {'; '.join(_chapter_previews)}{_identity_section}{_grounding_constraint}"""
```

- Activated only when `STORIED_MODE=true` AND spine generation succeeds
- Calls GPT-3.5-turbo (temperature 0.8, max_tokens 380)
- Stored in `_saved_prolog` (declared at line 4650)

### Prolog injection into Stop 1 (lines 6594-6595)

```python
# [R2] For Stop 1: inject prolog before description
if i == 0 and _saved_prolog:
    poi_content += f"{_saved_prolog}\n\n"
```

### Additional Stop 1 exclusives

- **Museum Information** (hours/admission): line 6580 — `if tour_category == 'museum' and i == 0`
- **Entrance directions** (non-museum): prepended to orientation
- **Coordinates** (museum): only Stop 1 shows them

### Fallback path (LOCAL-119, lines 6430-6460)

If prolog LLM fails: (a) Stop 1's first two description sentences,
(b) raw `tour_hook`, (c) empty.

## 3. Verdict: Is the effect real and systematic?

**Yes.** The effect is structural and deterministic:

1. Every STORIED_MODE tour injects 658-933 chars of **tour-level** text
   into Stop 1 before its POI description.
2. This text names the tour, the region, previews other stops, and uses
   journey/chapter metaphors — none of which pertains to Stop 1's POI.
3. Michael is correct that NO_ANCHOR is the right classification for this
   text (it's not about the stop), and that a scene-setting opener is fine
   *as long as the stop's own story follows*. The fault is that it crowds
   Stop 1 by placing tour framing and POI content in the same slot.
4. The ANCHORED rate for Stop 1 vs rest is nearly identical (10% vs 8%)
   because both have similar corpus coverage — the prolog just adds bulk,
   not anchored content.

## 4. What separating it would touch

If the prolog belongs in its own slot (e.g., a "Tour Introduction" section
before Stop 1):

| Component | Change needed | Risk |
|-----------|--------------|------|
| `generate_tour_text.py` line 6594 | Emit prolog as standalone section above Stop 1 | Low — 2 lines |
| `parse_tour_stops()` in detectors | Recognize Introduction as non-stop content | Low |
| Flutter app tour player | New rendering path for Introduction section | Medium |
| Tour delivery / existing tours | 117 tours have prolog inside Stop 1; migration | Medium |
| `docker-compose` / containers | No rebuild needed if format change only | None |

**Risk assessment:**
- Low code risk (1 injection point, clear boundary)
- Medium integration risk (app player must handle new section; existing tours need migration or backward compat)
- The prolog is good content — the fault is placement, not quality

## Limitations

1. **Tour framing rate has noise in cycling tours.** "French Riviera" matches
   the region pattern in every stop of tours 29/152/156, inflating the rest's
   framing rate. The prolog detection (looking for "You are about to embark")
   is a more reliable signal than the framing regex.
2. **Only 1 tour (162) lacks a prolog** — it's a single-stop test. Cannot
   measure STORIED_MODE=false behavior from this sample.
3. **ANCHORED rate nearly identical** (10% vs 8%). The prolog doesn't
   reduce anchor quality — it adds unanachored bulk alongside normal content.
4. **No generation changes made.** This is measurement only.
5. **audio_tours count:** 117 (unchanged, verified).

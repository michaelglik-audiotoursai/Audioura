## 2. A tour made FOR a community (D663 §3)

A generated tour can belong to a community. Migration 035 adds two additive, inert-by-default
columns on `audio_tours`:
- `community_id INTEGER` — the owning community (NULL = ordinary public tour, unchanged). FK
  to `communities(id)` `ON DELETE SET NULL` (removing a community never deletes the tours).
- `community_visibility VARCHAR(16)` — `'members'` (default) or `'public'` (CHECK-constrained).

### Backend
- **`community_tours_service.py` (NEW, repo root)** — self-contained apart from the shared
  test DB helper, mirroring `tour_pricing_service.py` so it registers on the orchestrator and
  imports in tests without pulling in Flask. It owns:
  - `tag_community_tour(cur, tour_id, community_id, visibility, owner_user_id)` — validates the
    community exists & is not disabled (`unknown_community`), the caller OWNS it (`not_owner`),
    the tour exists (`unknown_tour`), and a `public` tour has coordinates
    (`public_needs_location`); then writes `community_id` + `community_visibility`.
  - `community_tours_for_member(user_id, community_id)` → `{community_id, is_member, tours}` —
    the tour list for the community page, **populated only for an active member or the owner**;
    a non-member/expired member gets an empty list (members-only hidden, D658 §2).
  - `community_download_decision(cur, user_id, tour_id)` → `(relevant, allowed, deny)` — a
    community tour is gated by MEMBERSHIP, not price; a non-member gets
    `402 {"error":"membership_required","community_id":…,"tour_id":…}`.
  - `register_community_tour_routes(app)` — `POST/GET /tour/<id>/community`,
    `GET /communities/<id>/tours?user_id=`.
- **`tour_orchestrator_service.py`** — registers the community-tour routes (defensively, next
  to the pricing routes); the `generate-complete-tour` route parses `community_id` +
  `community_visibility`; `ACTIVE_JOBS` carries them; after the stored tour's id is resolved it
  tags the row via `community_tours_service` (own short-lived connection, non-fatal — a tagging
  failure never fails an already-delivered tour). The tour is generated by the **normal
  pipeline** (D656 content rating + review queue) and **charged to the organiser** — the
  generate path already charges the requesting `user_id`, who IS the organiser, so no change to
  the charging/allowance code was needed.
- **`map_delivery/app.py`** (the listing + download service of record) — added self-contained
  community helpers (`_has_community_columns`, `_community_tag`, `_community_tags_batch`,
  `_community_name`, `_is_active_member`, `_community_download_decision`):
  - `_download_gate` checks the **community** branch FIRST: an active member/owner is allowed
    (members download free of extra charge — D660 per-download rules do NOT apply to community
    tours); a non-member gets `402 membership_required`. A community tour's `price_tier` stays
    NULL, so `consumes_unlock` is False — no D660 unlock consumption.
  - `/tours-near` and `/search-tours` batch the community tags (one query, no N+1), **SKIP
    members-only** tours, and add the community **badge** fields (`community_id`,
    `community_name`, `community_visibility`, `badge='community'`) to **public** ones. Content
    rating (D656) still filters first, so a `not_allowed` public community tour stays hidden.
- **`user-tracking/communities_api.py`** — added `GET /communities/mine-owned?user_id=` (the
  non-disabled communities a user owns) so the Generate tab can offer the "For:" selector only
  to organisers.

## 1. Requirements

Replace the single hardcoded 🗺 map button emoji with a tour-type-specific icon:

| Tour category | Icon |
|---|---|
| `walking` | 🚶 |
| `restaurant` | 🍴 |
| `museum` | 🏛️ |
| `specialized` / default / unknown | 🗺 |

The icon must appear identically in:
- English tours (generated by `tour_generation_modernized.py`)
- Translated tours (Russian, French, Chinese — generated by `translation_service.py`)

## 2. Data Flow Analysis

### How tour_category reaches tour_generation_modernized.py

```
generate_tour_text.py
  → _classify_tour_category(location, tour_type) → 'walking'|'restaurant'|'museum'|'specialized'
  → writes .txt file with title line:
      "Step-by-Step Audio Guided Tour: {location} - {tour_type.title()} Tour"
  → e.g. "Step-by-Step Audio Guided Tour: Newton Center, MA - walking Tour"

tour_orchestrator_service.py
  → POST 5021/process  {"tour_file": "newton_center_walking_tour_XXXX.txt"}

tour_generation_modernized.py
  → parse_tour_content_to_modernized() extracts tour_name from title line
  → generate_html_with_external_audio(tour_data) receives tour_name
```

`tour_category` is NOT passed as a separate field — it is embedded in the tour title string
as `"- {category} Tour"` (e.g. `"- walking Tour"`, `"- museum Tour"`).

### Real tour titles from DB (confirmed):
```
ID 150: "walking tour in Newton Center, MA - walking Tour"
ID 243: "restaurant tour in Newton, MA - museum Tour"   ← _pre_category guard active
ID 259: "Jackson Homestead and Museum Newton, MA - museum Tour"
```

### Translation path — icon survives for free

`translation_service._create_mobile_compatible_zip()` (modernized format path):
1. Extracts English `index.html` from original ZIP
2. Parses with BeautifulSoup
3. Calls `h.clear()` + `h.append(NavigableString(...))` on `<h3>` tags — translates heading text
4. Replaces `audio_N.mp3` files with translated Polly audio
5. Writes updated HTML back to ZIP

The map button is a **sibling** of `<h3>` inside `.audio-item`, not a child:
```html
<div class="audio-item">
    <h3>Stop title: Audio 1</h3>   ← h.clear() only clears h3's own children
    <button class="map-btn" ...>🚶</button>   ← sibling — untouched by h.clear()
    <audio ...>
```

**Conclusion**: The icon baked into English HTML survives translation unchanged. ✅
No changes needed in `translation_service.py`.

## 3. Implementation

### Changes to `tour_generation_modernized.py` only

#### 3a. New module-level regex and helper (added alongside existing `_COORDINATES_RE`):

```python
_TOUR_CATEGORY_RE = re.compile(r'-\s*(walking|restaurant|museum|specialized)\s+Tour', re.IGNORECASE)

def _tour_icon_for_name(tour_name):
    """Return tour-type emoji based on category embedded in tour title."""
    m = _TOUR_CATEGORY_RE.search(tour_name)
    if not m:
        return '🗺'
    cat = m.group(1).lower()
    return {'walking': '🚶', 'restaurant': '🍴', 'museum': '🏛️'}.get(cat, '🗺')
```

#### 3b. Updated map button in `generate_html_with_external_audio()`:

Before:
```python
map_button = f'<button class="map-btn" onclick="openMap({i})" title="View on map">🗺</button>'
```

After:
```python
icon = _tour_icon_for_name(tour_name)
map_button = f'<button class="map-btn" onclick="openMap({i})" title="View on map">{icon}</button>'
```

`tour_name` is already in scope at the top of `generate_html_with_external_audio()`.

#### 3c. Version bump:
`SERVICE_VERSION = "1.2.5.177"` → `"1.2.5.178"`

## 5. Review Questions for Claude.AI

**Q1 — Regex correctness**: The pattern `r'-\s*(walking|restaurant|museum|specialized)\s+Tour'`
matches `"- walking Tour"` in the title. Is this robust enough, or could it false-match
something like a stop name containing "- walking Tour"? (Note: `tour_name` is the full
tour title string, not a stop name.)

**Q2 — `specialized` icon**: `specialized` falls through to the default `🗺` via `.get(cat, '🗺')`.
Is it cleaner to include `'specialized': '🗺'` explicitly in the dict, or is the fallback
approach acceptable?

**Q3 — Translation survival**: The analysis concludes the icon survives `h.clear()` because
the button is a sibling of `<h3>`, not a child. Is this BeautifulSoup behavior reliable —
does `h.clear()` strictly clear only the tag's own children and never touch siblings?

**Q4 — Icon rendering**: 🏛️ uses a variation selector (`U+FE0F`) to force emoji presentation.
Is this safe in all mobile WebView environments (iOS WKWebView, Android WebView)?
Could it render as a text glyph on some devices?

**Q5 — Single point of truth**: The icon is determined once at HTML generation time and
baked in. If a user regenerates a tour, the new icon reflects the current category.
Old tours in the DB keep their old icon. Is this acceptable, or should the icon be
determined at render time (which would require Flutter-side logic)?
